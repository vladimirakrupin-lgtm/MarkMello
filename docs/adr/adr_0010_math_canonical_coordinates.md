# ADR-0010: Канонические координаты формул

## Status

Утвержден (решение владельца по follow-up ревью `feat/math-rendering`)

## Date

2026-11-17

## Context

ADR-0009 ввёл рендер LaTeX: inline-формула занимала **один** placeholder-символ
в styled text (`\uE002`), а блочная формула жила только как visual и не
участвовала в document-wide selection. При этом канонический текст документа
(`MarkdownDocumentTextMap`) хранил для формулы **весь TeX**
(`math.Content` / `math.Source`).

Две разные модели одной и той же формулы дали рассинхрон координат:

- `A $x^2$ B`: текстовая карта — `A x^2 B` (7 символов), styled text — `A <ph> B`
  (5). Любая арифметика смещений (`DocumentRange` фрагмента,
  `MarkdownSelectionTextFragment.GetDocumentOffset`,
  `TryScrollToActiveMatch`) съезжала на `latex.Length - 1` сразу после формулы;
- выделение мышью видело в формуле placeholder шириной в один пробел, а не
  нарисованную формулу;
- блочные формулы не были зарегистрированы как selection-фрагменты: их нельзя
  было выделить, а поиск, найдя совпадение, не подсвечивал и не прокручивал
  к формуле.

## Decision

Канонический текст — один на весь документ: **формула присутствует в нём полным
TeX** (как уже делал `MarkdownDocumentTextMap`). Сжимается только **отображение**.

1. **Inline.** `MarkdownStyledText` пишет в styled text весь `MarkdownMathInline.Content`;
   `MarkdownMathSpan.Range` покрывает этот же диапазон. Раскладка
   (`MarkdownDisplayLayoutModel`) заменяет диапазон одним `MarkdownMathTextRun`,
   который рисует формулу, и одним `MathContinuation`-сегментом на каждый
   следующий символ TeX — каретки и подсветка остаются 1:1 с текстовой картой,
   а ширина на экране равна ширине диапазона.
2. **Блочные.** `MarkdownMathBlock.Source` — тоже часть канонического текста.
   Visual блока (`MarkdownMathSelectionFragment`) регистрируется в
   `_selectionFragments` с диапазоном своей формулы. Гранулярность — **блок
   целиком**: каретка встаёт на начало формулы, двойной щелчок выделяет всю
   формулу, считанная мышью позиция внутри бокса — не текстовое смещение.
3. **Копирование** берёт TeX из канонического текста (полный источник формулы,
   без долларов) — решение владельца: так формула при вставке остаётся формулой.
4. **Поиск** идёт по каноническому тексту, поэтому находит LaTeX. Диапазоны
   подсветки, задевающие формулу, видны на её нарисованном боксе (в тексте —
   через карту кареток, у блока — как диапазон самого фрагмента).
5. **Кэш измерений** (`MarkdownMathRenderer`) индексируется по
   **нормализованному** LaTeX, чтобы `\lVert` и его алиас делили одну запись.

## Considered alternatives

- **Один placeholder-символ в каноническом тексте** (то, что предлагалось
  изначально как «проще»). Отклонено владельцем: карта документа перестала бы
  хранить TeX, и копирование, поиск по источнику и plain-text представление шли
  бы в обход канонического текста — пришлось бы реконструировать содержимое
  формулы в каждом потребителе. Также потребовало бы второго канала
  «что копировать для формулы».
- **Посимвольное выделение блочной формулы по её LaTeX.** Отклонено: у блока
  нет текстового лайаута (формула — одна нарисованная картинка), посимвольные
  каретки по невидимому тексту не отражают ни экрана, ни смысла. Блок целиком
  согласуется с «одна нарисованная единица — один selection-фрагмент».

## Consequences

Positive:

- текстовая карта и styled text совпадают по длине и смещениям — выделение,
  копирование и поиск формул работают без отдельной арифметики;
- блочные формулы стали полноправными selection-фрагментами (выделение,
  подсветка, прокрутка к совпадению);
- смысл формулы никогда не теряется: TeX всегда есть в каноническом тексте.

Negative / ограничения:

- на экране формула выглядит уже своего текста — ширина меньше, чем у
  `latex.Length` символов; это осознанный компромисс ради того, чтобы каретка,
  попадающая в формулу, визуально оказывалась на нарисованной формуле;
- гранулярность блочной формулы — блок целиком (см. решение 2);
- `$$...$$` внутри параграфа остаётся inline-формулой и отображается как
  формула, но копируется своим LaTeX-источником.

## Scope of changes

- Domain: `MarkdownDocumentTextMap` (TeX формулы — каноническая модель).
- Presentation: `MarkdownStyledText`, `MarkdownDisplayLayoutModel`,
  `MarkdownMathTextRun`, `MarkdownMathContinuationTextRun`,
  `MarkdownFormattedTextLayout`, `MarkdownMathSelectionFragment`,
  `MarkdownDocumentView.Math`, `MarkdownDocumentView.Search`,
  `MarkdownMathRenderer` (нормализованный ключ кэша).
- Tests: `MarkdownMathSelectionTests` (выделение, копирование, поиск,
  подсветка, расчёт прокрутки).

## Acceptance criteria

- `A $x^2$ B`: длины текстовой карты и styled text равны; каноническая позиция
  сразу за формулой — это позиция `B`;
- выделение только формулы копирует её TeX; выделение через формулу включает её
  один раз;
- поиск внутри inline- и блочной формулы даёт совпадение, подсветку и позицию
  прокрутки к фрагменту;
- блочная формула выделяется как единое целое, а невалидный LaTeX остаётся
  выделяемым исходником.
